Редизайн хранения данных стандартов: structure.json v2 — иерархия «Контейнер (КЭТ) → Шкаф → Комплект (0…n ИЭУ)»

## Контекст

Сейчас structure.json — два плоских списка («Шкаф» 308 записей и «комплекты» 339), построенных «по образцу standards/structure.json». Проблемы: связи замаскированы под поля данных («Комплект 1» хранит id, поле «Шкаф» совпадает с именем раздела), ИЭУ нет как сущности (таблицы по ИЭУ приклеены к комплекту без атрибуции), контейнеров в структуре нет вовсе, формы значений неедины (таблицы-словари с цифровыми ключами, маркер-строки, заглушки «нет данных»), спецификация формата нигде не зафиксирована.

Утверждено с пользователем: формат образца больше не обязателен (свободный редизайн), контейнеры входят в тот же файл. Целевая модель: **Контейнер ⊃ Шкаф ⊃ Комплект ⊃ (0…n) ИЭУ**. Комплект принадлежит ровно одному шкафу → комплекты вложены в запись шкафа. Шкаф может быть вне КЭТ и в нескольких КЭТ (25 таких, напр. ket-shrot) → контейнер хранит ссылки на шкафы, шкаф — обратный массив «контейнеры».

## Схема v2 (фиксируется в STRUCTURE.md)

```json
{
  "версия": 2,
  "описание": "...",
  "сущности": {"контейнер": "…", "шкаф": "…", "комплект": "…", "иэу": "…"},
  "источники": {...},
  "контейнеры": [ { "id", "код", "название", "группа", "типоразмер", "слотов",
                    "стандарт", "функции": [], "состав": [], 
                    "шкафы": ["shet-…"], "источник" } ],
  "шкафы": [ { "id", "шифр", "наименование", "полное имя", "назначение",
               "архитектура ПС", "защищаемый элемент", "управляемый элемент",
               "вводы питания", "порты", "основные компоненты": [], "класс напряжения",
               "группа", "стандарт", "функции ИТС": [], … (прочие поля как сейчас, без суффиксов «шкафа»),
               "контейнеры": ["ket-…"],
               "комплекты": [ { "номер", "вид", "полное имя", "назначение", "шифр",
                                "функции РЗА": [], "теги": [],
                                "входные аналоговые измерения": [ {строка таблицы} ],
                                "внутренние дискретные цепи": [ {строка} ],
                                "иэу": [ { "обозначение", "тип", "описание",
                                           "входные GOOSE": [], "выходные GOOSE": [],
                                           "функциональные клавиши": [], "светодиодная сигнализация": [],
                                           "команды управления от АСУ ТП": [], "аналоговые значения": [],
                                           "отчеты в АСУ ТП": [], "источник" } ] } ] } ]
}
```

Правила (устраняют все 6 проблем):
- **Служебные ключи** — фиксированный документированный набор (id, контейнеры, шкафы, комплекты, иэу, номер, версия, описание, сущности, источники, источник); всё остальное — содержательные поля. Угадывание по маскам `startswith("Комплект ")` исчезает.
- **ИЭУ — сущность**: таблицы стандарта (GOOSE, ФК, СИ, команды, аналоговые значения, отчёты) лежат под конкретным ИЭУ. Привязка по индексу: IEDn исходника → `иэу[n-1]`; если у исходника один блок, а в комплекте несколько ИЭУ — блок дублируется каждому с `"источник": "общая таблица (без разделения по ИЭУ)"`. Пустой «иэу»/отсутствие поля = «комплект без ИЭУ» (as is: has_ied).
- **Формы значений едины**: таблицы — всегда массивы строк-объектов; списки — массивы строк; отсутствующие данные — поле опускается (никаких «нет данных», `{"1": …}`, `"- x\n- y"`).
- **Контейнеры**: раздел из `containers.all_containers()`; шкаф-level GOOSE и «Испытательные блоки» (когда данные по шкафу целиком) остаются полями записи шкафа — вложение снимает двусмысленность имён.
- id сохраняют ключи каталога редактора (`shet-…`, `typ:…:n`) — стыковка со схемами не меняется.

## Изменения по файлам

1. **tools/build_structure.py** — переработка сборки: раздел «контейнеры» из `containers.all_containers()`; шкафы с вложенными комплектами и ИЭУ; обратные «контейнеры» вычисляются; `numbered()`/`dash_list()`/`NO_DATA` удаляются; шапка v2. Источники данных прежние (standards/src, cabs_analog, cabs_signals, extracted.json).
2. **structure.py** — разделы «контейнеры»/«шкафы»; индексы строятся из вложенности (kits_by_id из записей шкафов) и хранятся **в модуле, не внутри документа** (сейчас `_cabinets_by_id` пишутся внутрь загруженного JSON); API сохраняется (`cabinet/kit/kit_for/kits_of/format_record/format_cabinet_full/summary/available/reload/error/path`), добавляется `container(key)`; `format_record` рендерит вложенность («иэу», таблицы-массивы) рекурсивно, маски-пропуски удаляются; `cabinets_of` становится реально используемой (окно контейнера).
3. **tools/check_structure.py** — проверки v2: уникальность id; двусторонняя согласованность «контейнер.шкафы ↔ шкаф.контейнеры»; вложенные комплекты vs `komplekts.cabinet_komplekts()`; стыковка со схемами; форма-линт (запрет цифровых ключей-таблиц и «нет данных»); статистика заполнения по новым полям.
4. **tests/test_structure_docking.py** — правки утверждений под v2 (`шифр`, `иэу[0]["обозначение"]`, аналоговые — массив из 11 строк), GUI-часть без изменений.
5. **main.py** — точечно: чтения полей (1659–1662, 1684, 1692–1693: «Шифр шкафа»→«Шифр», «Полное имя комплекта»→«Полное имя»), ветка контейнера в `show_selected_structure` (1725–1731) через `structure.container()` + `cabinets_of()`, подсказки «по образцу standards/structure.json» → описание v2.
6. **STRUCTURE.md** — переписывается как спецификация формата v2 (поля каждой сущности, правила форм), пайплайн сборки прежний, упоминание образца убирается.

`structure.json` не мигрирует — пересобирается скриптом (он и так вне git).

## Проверка

1. `python tools/recover_kb_docs.py` — восстановить standards/src (база знаний на месте); `python tools/extract_standards.py` — выгрузка из PDF (кэш, если уже есть — пропустить).
2. `python tools/build_structure.py --stats` — собрать v2: 17 контейнеров, 308 шкафов, 339 комплектов; ИЭУ-таблицы под своими ИЭУ.
3. `python tools/check_structure.py` — 0 ошибок (ссылки замкнуты в обе стороны, формы едины, стыковка со схемами 17/17).
4. `python tests/test_structure_docking.py` — ок (GUI-часть при наличии дисплея).
5. `python structure.py shet-211-01-1` — человекочитаемый вывод с вложенными комплектами и ИЭУ; визуально: окна «Структура» в редакторе (Шкафы→Каталог→Структура, Комплекты→Структура, Ctrl+E на контейнере).
