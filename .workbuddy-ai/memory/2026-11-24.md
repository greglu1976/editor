## Четыре старых падения тестов — устранены

- Причина 1: `es.files()` принимал за стандарт `EA/ЗВП.json` (это схема ФЛС:
  `elements`/`connections`/`logic_links`), из-за чего `normalize_document`
  добавлял реквизиты. Добавлен `es.is_standard()`, `files()` фильтрует JSON
  по наличию `sections` или `cabinets`.
- Причина 2: `Отчет о НИР.json` содержит те же четыре шифра, что и том 5,
  и по алфавиту идёт раньше; дедупликация в `ea_merge.catalog()` оставляла
  их под меткой «Отчет о НИР», поэтому в каталоге не было «т. 5». Теперь
  при обходе по умолчанию файлы томов идут первыми (для явного списка
  `paths` порядок сохраняется).
- Причина 3: в `Отчет о НИР.json` номера 4 комплектов и в
  `Отчет по НИР.json` номер одного ИЭУ были строками вместо `i` из схемы.
  Значения переведены в int в самих JSON (5 строк diff).
- Итог: `tests/test_ea_features.py` и все остальные модули тестов
  проходят полностью. Изменения не коммитил (коммит `c1e3d87 fix 31`
  сделан пользователем до этих правок).

## Пункт 33 tasks.txt — разделённое описание шкафа

  только по «описание шэт». Добавлен вид `description_kit` с подстрокой

- Реквизит `description_split` (bool) добавлен в схему как EXTRA_FIELD,
  в диалог нового стандарта и в панель/диалог реквизитов; `ns.build()`
  включает его по умолчанию для новых стандартов.
- `st.split_description_tables()` при флаге меняет единую форму на 8 полей
  шкафа и 19 полей ИЭУ, группирует идентичные комплекты по `Kit.identical`

  идемпотентна. Старые стандарты без флага не трогаются.
- В редакторе добавлена кнопка «Обновить стандарт»: split + `ns.renumber_standard`,
  после чего обновляются дерево и статус. Повторное нажатие не дублирует формы.
- Тесты: `test_split_descriptions`, `test_editor_update_standard`, проверки
