# 2026-11-11

## Извлечение шкафов из DOCX по UML-модели EA

Задача: по XMI-схеме `EA/structure.xml` (экспорт Enterprise Architect, 24 элемента
классов / 23 уникальных имени) вытащить шкафы из
`EA/Раздел 4.16_т. 5_СТО ШЭТ СКРМ II_Ред.2.docx`.

* Добавлен `tools/docx_to_uml.py`: читает XMI (классы, атрибуты с типами,
  ассоциации), разбирает DOCX через существующий `tools/docx_to_standards_json.py`
  (`convert(..., dry_run=True)`, восстанавливает автонумерацию таблиц), маппит
  14 таблиц каждого шкафа в UML-сущности и валидирует результат по модели
  (ключ = атрибут класса или связанный дочерний класс).
* Выход: `EA/cabinets_uml.json` (1,2 МБ) и `EA/cabinets_uml_report.md`.
  4 шкафа (5.3–5.6, ШЭТ 431.11-1 … 431.14-1), 1 комплект и 1 ИЭУ на шкаф,
  1788 Signal, 254 Parameter, 139 Function, 129 Terminal, 27 DataSet.
* Ключевые решения по маппингу: `Cabinet` ← карточка «Описание ШЭТ»;
  `CabinetReport` — сводка с `components`; GOOSE-наборы `dsgo_*` вложены в
  `OutcomingMessage.DataSet`, отчёты `dsrpt_*` — в `IED.DataSet`, их описания —
  в `IED.OutcomingReport`; `Function.isMainFunction/isInITS` из полей «Основные
  функции»/«Функции ИТС» с раскрытием синонимов в скобках; «» (ditto) развёрнуты.
* Оговорки модели: в XMI два `TerminalRow` и кольцевые композитные связи —
  использована иерархия таблицы `Kit.TerminalBlock → TerminalRow → Terminal`,
  `Kit.IED` добавлен как обратная к `IED → Kit` связь. Атрибуты `iec_name`,
  `russian_path`, `*.note`, `source_number`, `canal` в стандарте колонок не имеют.
* Проверка: ошибок валидации нет; 8 строк «Разделитель цепи» осознанно пропущены.

## Расширяемый каркас редактора

* Выбран безопасный вариант: `main.py` остаётся неизменённым рабочим
  графическим движком; новый запуск — `editor_app.py`, адаптер движка —
  `editor_engine.py`. Старый `python main.py` продолжает работать.
* Слой структур вынесен в `structure_core` (контракт `StructurePlugin`,
  `StructureRegistry`, трёхпанельный `StructureManagerWindow`) и `structures`
  (`manifest.json`, рабочий плагин `ea_cabinets`, точки расширения `sto` и
  `containers`). Слой структур не импортирует `main.py`, `library.py`,
  `cabs.py`, `komplekts.py`, `structure.py` и каталоги старой структуры.
* Новая вкладка `UML структуры` добавляется через адаптер движка без правки
  `main.py`: реестр структур, обновление manifest, быстрый доступ к чертежу
  шкафов EA и сборке шкафа. Менеджер рисует схему «движок → реестр → плагины».
* Для будущих UML-схем достаточно записи в `structures/manifest.json` и
  модуля с `create_plugin(config, root)`; рабочее окно реализует
  `create_workspace()`, при необходимости — `create_assembly()`.
* Проверено: `editor_app.py --selftest` (11 проверок, состояние движка не
  изменилось), headless-открытие менеджера/чертежа/сборки, обновление реестра,
  `main.py --selftest` с временным отчётом, py_compile на Python 3.10/3.14,
  AST-проверка изоляции 8 файлов слоя структур.
