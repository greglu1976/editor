# Сборка приложения: exe и папка `db`

Да, «Редактор схем» собирается в exe (PyInstaller — это и есть движок
auto-py-to-exe) в режиме **One Directory**, а все файлы данных лежат рядом с
exe в отдельной папке **`db`**. Внутрь exe они не зашиваются: их можно
править, копировать на другой компьютер и хранить в системе контроля версий,
не пересобирая программу.

## Что получается

```
dist/
  Редактор схем/
    Редактор схем.exe
    _internal/              служебные файлы PyInstaller (не трогать)
    db/
      cabinets.json         каталог шкафов: правки и пользовательские шкафы
      cabs_signals.json     сигналы и испытательные блоки из СТО
      cabs_analog.json      входные аналоговые измерения из СТО
      containers.json       контейнеры КЭТ
      komplekts.json        комплекты (появляется после первой правки)
      structure.json        структура v3: КЭТ → шкафы → комплекты → ИЭУ
      standards_base/       стандарты СТО в JSON (3 файла, 3,8 МБ)
      standard_editor/      редактор изменений стандартов, базы и изменения
      tools/                build_structure.py, check_structure.py
      README.txt            что здесь лежит
```

Объём `db` — около **16,6 МБ** (каталоги, структура и стандарты). PDF
стандартов (361 МБ) и черновики `standard_editor/_parse` в сборку не
попадают: они нужны только инструментам разработчика.

## Как собрать

```bash
python build_exe.py --check      # что есть, чего не хватает (ошибок: 0)
python build_exe.py --stage      # только папка db → dist/Редактор схем/db
python build_exe.py              # db + exe (PyInstaller, One Directory)
python build_exe.py --onefile    # один exe, папка db всё равно рядом
```

`build_exe.py` сам собирает `db`, рисует `assets/editor.ico` (из `appicon.py`,
нужен Pillow), вызывает PyInstaller и после сборки запускает проверку
`Редактор схем.exe --selftest`. Если PyInstaller не установлен, скрипт скажет
это и всё равно соберёт `db` — сборку можно повторить в auto-py-to-exe.

## Те же значения в auto-py-to-exe

| Поле auto-py-to-exe | Значение |
|---|---|
| Script Location | `main.py` |
| Onefile | **One Directory** |
| Console Window | **Window Based (hide the console)** |
| Icon | `assets/editor.ico` (сначала `python build_exe.py --icon`) |
| Name | `Редактор схем` |
| Additional Files | **—** (папка `db` копируется рядом с exe, а не внутрь) |
| Advanced → `--paths` | папка проекта |

После сборки положите `db` рядом с exe:

```bash
python build_exe.py --stage
```

или скопируйте папку `db` из готового `dist` вручную. `python build_exe.py
--auto-py-to-exe` печатает эти же поля с путями текущего проекта.

## Как программа ищет файлы

Порядок задан в [`apppaths.py`](apppaths.py):

1. `$EDITOR_DB` — если задана переменная окружения (переносимая папка данных,
   например на сетевом диске);
2. `<папка exe>/db` — обычная раскладка собранного приложения;
3. `<папка exe>/<файл>` — плоская раскладка: так работают исходники в
   репозитории, где `cabinets.json` и `structure.json` лежат в корне;
4. `<_MEIPASS>/db/<файл>` и `<_MEIPASS>/<файл>` — данные, упакованные внутрь
   onefile (только чтение: временная папка исчезает при закрытии).

Файла нет нигде — путь всё равно указывает в `db`: там его создаст первое
сохранение. Поэтому после установки на чистую машину программа запускается и
создаёт `komplekts.json` сама, а `structure.json` и каталоги должны быть
положены при установке.

**Записи из папки `db` главнее.** Если рядом с exe лежит `db/cabinets.json`,
файл в корне (если он там остался) не читается. Двух копий быть не должно:
либо `db`, либо плоская раскладка.

## Проверка сборки без окна

```bash
"dist/Редактор схем/Редактор схем.exe" --selftest
```

Пишет `selftest.json` рядом с exe: папка данных, какие файлы найдены и
откуда, сколько шкафов в структуре и стандартов в `standards_base`, доступен
ли редактор изменений. Возвращает код 0, если обязательные файлы на месте.
Эту же проверку выполняет `build_exe.py` после сборки.

## Про DOCX

Отчёт Word строит `standard_editor/json_to_docx.py`, ему нужен
`python-docx`. Если пакет установлен в том Python, которым собирают exe,
PyInstaller заберёт его в сборку и DOCX будет работать внутри приложения.
Если нет — программа ищет внешний интерпретатор с `python-docx` (в
разработке это `C:\Python313`), а на чужой машине покажет подсказку
`pip install python-docx`. Для полноценной сборки ставьте пакет до сборки:

```bash
py -3.13 -m pip install python-docx pyinstaller
py -3.13 build_exe.py
```

## Ограничения

* **PyInstaller и auto-py-to-exe** в этом окружении не установлены, сети для
  `pip` нет — поэтому exe здесь не создан. Скрипт, макет `db`, иконка и
  проверки готовы: на машине с PyInstaller достаточно `python build_exe.py`.
* **onefile** запускается, но папка `db` должна лежать рядом с exe; внутрь
  одного файла её не кладут, иначе правки пользователя пропадали бы после
  закрытия (временная папка распаковки удаляется).
* **Пересборка структуры** (вкладка «Структура» → «Пересобрать») работает из
  `db/tools/build_structure.py` и пишет `db/structure.json`; исходные JSON
  `standards/src` в сборку не входят, поэтому пересборка использует уже
  готовый `structure.json` и `standards_base`.
* **`standards/`** (PDF, `extracted.json`, `src`) остаётся папкой разработчика:
  это инструменты извлечения из PDF, а не работа редактора.
* **Иконка** `assets/editor.ico` — генерируемый файл (23 КБ, 7 размеров);
  её можно положить в git, чтобы сборка не зависела от Pillow.

## Что проверяет тест

```bash
python tests/test_packaging.py
```

Девять групп: `apppaths` и порядок поиска, переменная `EDITOR_DB`, план
сборки, сборка `db`, чтение модулей из `db` в отдельном процессе, `--selftest`,
имитация замороженной сборки (`sys.frozen`, `_MEIPASS`), иконка и командная
строка `build_exe.py`.
