# Структура шкафов и комплектов (`structure.json`)

Единая структура шкафов и комплектов РЗА по образцу
[`standards/structure.json`](standards/structure.json) — для редактора
электрических схем [`main.py`](main.py).

Сейчас в файле **308 шкафов и 339 комплектов** — всё, что знает каталог
редактора (`cabs.all_cabinets()`), включая пользовательские правки из
`cabinets.json`.

## Как собрать / пересобрать

```bash
python3 tools/recover_kb_docs.py        # 1. исходники по ИЭУ из базы знаний «Исходные»
python3 tools/extract_standards.py      # 2. «Назначение шкафа» и «Основные компоненты» из PDF
python3 tools/build_structure.py --stats  # 3. сборка structure.json
python3 tools/check_structure.py        # 4. проверка полноты и стыковки
python3 tests/test_structure_docking.py # 5. тесты (модуль, схемы, окна редактора)
```

Шаги 1–2 кешируются: `standards/src/*.json` и `standards/text_cache/`
(по файлу на документ) + `standards/extracted.json`.

## Место в git

В репозитории — код: [`structure.py`](structure.py) (модуль доступа),
`tools/*` (сборка и проверки), `tests/test_structure_docking.py`,
[`STRUCTURE.md`](STRUCTURE.md) и правка [`main.py`](main.py).
Сам **`structure.json` — генерируемый артефакт и в `.gitignore`**: его нужно
собрать после свежего клона (`tools/build_structure.py`). Образец структуры
хранится отдельно — `standards/structure.json` (папка `standards/` с PDF тоже
вне git, поэтому шаг 2 работает только там, где лежат стандарты).

## Формат

Плоский JSON: два списка — «Шкаф» и «комплекты» (образец: *«комплекты, шкафы в
разных местах, ссылки по ключам»*). Идентификаторы — **ключи каталога
редактора**, поэтому дополнительного маппинга не нужно:

| Запись | `id` | пример |
|---|---|---|
| шкаф | `key` шкафа каталога | `shet-211-01-1` |
| комплект | `key` комплекта каталога | `typ:shet-211-01-1:0` |

Связи: в шкафу — `"Комплект 1": "typ:shet-211-01-1:0"`, в комплекте —
`"Шкаф": "shet-211-01-1"`.

Поля шкафа (имена — как в образце): «Полное имя шкафа», «Назначение шкафа»,
«Шифр шкафа», «Архитектура построения ПС», «Наименование шкафа»,
«Защищаемый элемент», «Управляемый элемент», «Вводы питания оперативного
постоянного тока», «Основные компоненты шкафа» + строки таблицы «Описание ШЭТ»
из СТО (порты, класс напряжения, функции ИТС, применимость, ссылки на рисунки и
таблицы, «Теги»).

Поля комплекта: «Обозначение ИЭУ», «Полное имя комплекта», «Назначение
комплекта», «Шифр комплекта», «Вид комплекта», «Функции РЗА комплекта»,
«Состав ИЭУ» и таблицы по ИЭУ: «Входные аналоговые измерения»,
«Внутренние дискретные цепи», «Входные GOOSE сообщения»,
«Выходные GOOSE сообщения», «Функциональные клавиши со светодиодной
индикацией», «Светодиодная сигнализация», «Команды управления от АСУ ТП»,
«Аналоговые значения, формируемые ИЭУ», «Отчеты в АСУ ТП».
Колонки таблиц — как в стандарте: «Испытательный блок в шкафу»,
«Аналоговые измерения», «Количество контактов испытательного блока с учетом
регистрации его состояния», «Примечание»; «Дискретный сигнал» / «Направление»;
«Источник (физический)» / «Источник (логический, по МЭК 61850)» /
«Класс сообщения»; «Приемник» и т. д.

Внешние дискретные сигналы («Дискретные сигналы, формируемые ИЭУ») не
переносятся — этого требует образец. Если у шкафа несколько комплектов, а
сигналы в наработках заданы по шкафу целиком, GOOSE лежат в шкафу под ключами
«Входные GOOSE сообщения (шкаф)» / «Выходные GOOSE сообщения (шкаф)».

## Стыковка с редактором

Модуль [`structure.py`](structure.py) — единственная точка доступа:

```python
import structure
structure.available()                     # файл читается
structure.cabinet("shet-211-01-1")        # запись шкафа (по key или по шифру)
structure.kit_for("shet-211-01-1", 0)     # запись комплекта №1
structure.kits_of(key); structure.cabinets_of(keys_контейнера)
structure.format_cabinet_full(key)        # текст для окна/отчёта
structure.summary()                       # сводка по источникам и заполнению
```

В интерфейсе (`main.py`):

* **Шкафы → Каталог…** → кнопка «Структура» — шкаф и все его комплекты;
* **Комплекты → Каталог…** → кнопка «Структура» — запись комплекта;
* **Шкафы → Структура…** — сводка по файлу (источники, полнота);
* **Ctrl+E** — структура выделенного на схеме шкафа или контейнера КЭТ;
* в окне есть «Обновить из файла» — перечитывает `structure.json` без рестарта.

Ключ элемента схемы (`element.cabinet_key` / `element["cabinet"]["key"]`) и
ключ комплекта (`komplekts.typical_key(cabinet_key, index)`) — это и есть `id`
записи структуры; проверено на реальных схемах из `schemes/` (17/17 шкафов).

## Известные пробелы

1. **Внешние дискретные сигналы** справочно есть в `cabs_signals.json`, но в
   структуру не переносятся (требование образца).
2. **Толстые колонки таблиц СТО** (в «Функциональных клавишах»: краткое
   наименование ФК, состояния индикации «0»/«1», режим сигнализации; в
   «Светодиодной сигнализации»: обозначение на лицевой панели) в наработках
   потеряны — исходники БЗ хранят только наименования. Полные колонки есть в
   PDF; выгрузка — отдельная задача.
3. **«Основные компоненты шкафа»**: наименования и характеристики склеены в одну
   строку (`«Передняя дверь Обзорная (прозрачная)»`) — в PDF это соседние
   ячейки, а переносы строк внутри ячейки не позволяют разрезать их надёжно.
   Количество вынесено отдельно.
4. **14 шифров из СТО 296/297** (`ШЭТ 111.01-0/1`, `121.01-0/1`, `140.01-0/1`,
   `151.01-0/1`, `160.01-0/1`, `111.02-*`, `151.02-*`) есть в стандартах, но
   **отсутствуют в каталоге редактора** — чтобы попасть в структуру, их нужно
   добавить в `cabs_sto.py`.
5. **СТО 289, 290, 291, 292, 294, 295** (ШСО/ШСК, алгоритмы ОБР и пр.) не
   содержат разделов «Шкаф … типа ШЭТ …» — назначение/компоненты оттуда не
   выгружаются.
6. У **нетиповых и пользовательских** шкафов (копии, самодельные) поля
   стандартов пустуют по определению — структура отражает то, что есть в
   каталоге.
