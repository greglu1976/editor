# Интеграция `standard_editor` в редактор схем

`standard_editor/` — самостоятельный набор инструментов для работы со
стандартами СТО 56947007 в JSON: текстовый формат изменений `*.изм.txt`,
движок применения изменений, редактор изменений с окном, создание нового
стандарта на основе выбранного и отчёт Word. Раньше всё это запускалось
отдельным процессом (`run_changes_gui.bat`); теперь те же функции доступны из
редактора схем — вкладка ленты **«Стандарты»** (между «Структура» и
«Отчёты»).

## Что где лежит

| Файл | Роль |
|---|---|
| [`standards_editor.py`](standards_editor.py) | мост: находит папку, лениво импортирует модули, читает стандарты и изменения, собирает редакцию, создаёт стандарт, строит DOCX. Без tkinter — годится и для тестов, и для CLI |
| [`standards_ui.py`](standards_ui.py) | окна: список стандартов, редактор изменений, новый стандарт, сборка редакции, отчёт DOCX |
| [`main.py`](main.py) | вкладка «Стандарты» и пять методов-обёрток (`show_standards_window`, `open_standards_editor`, `show_new_standard_dialog`, `show_assembly_window`, `show_docx_window`) |
| `standard_editor/*.py` | исходные инструменты, не переписывались |

Модуль `standards_ui` импортируется по требованию: `import main` не тянет ни
окна стандартов, ни `changes_gui` (проверено — 0,31 с, как и раньше).

## Вкладка «Стандарты»

| Группа | Кнопка | Что делает |
|---|---|---|
| Стандарты СТО | «Стандарты…» | список JSON стандартов: файл, шифр, шкафы, таблицы, число изменений, папка, размер; двойной щелчок — редактор |
| Стандарты СТО | «Редактор изменений…» | `changes_gui.App` внутри окна редактора: дерево базы, таблица узла, операции, живой текст `*.изм.txt`, проверка, сборка, DOCX |
| Изменения | «Собрать редакцию…» | база + все изменения каталога → JSON редакции и журнал операций |
| Изменения | «Сбросить пометки…» | у выбранного стандарта убирает блок «Редакция», служебные поля отменённых строк («Статус», «Основание», «Действует до», «Изменение») и ссылки «(ИЗМ-1)» в тексте; сохраняет чистый JSON с уже применёнными правками |
| Изменения | «Новый стандарт…» | копия выбранного стандарта: реквизиты, набор шкафов, замены, перенумерация разделов |
| Отчёт | «DOCX…» | отчёт Word по стандарту или собранной редакции |

Редактор изменений открывается не отдельным процессом, а окном
(`tk.Toplevel`) внутри редактора: база загружается сразу, заготовка изменения
(`new_doc`) пересобирается под эту базу, поэтому поля `БАЗА` и `ХЭШ`
ссылаются на выбранный стандарт. Остальное поведение — как в
`changes_gui.py`: меню, горячие клавиши, журнал, `F5`/`F6`.

## CLI моста

```bash
python standards_editor.py --list                     # стандарты и счётчики
python standards_editor.py --check                    # разобрать *.изм.txt
python standards_editor.py --assemble --out редакция.json
python standards_editor.py --assemble --strict --ignore-hash
python standards_editor.py --docx редакция.json --docx-out отчёт.docx
```

## API `standards_editor`

```python
import standards_editor as se

se.available()                     # папка и движок на месте
se.standards()                     # список карточек стандартов
se.default_base()                  # база редактора изменений (279-2019)
se.change_files(); se.changes_summary(); se.changes_for(code)
se.compile_changes(folder)         # (compiled, errors) — без записи
se.assembly(base, folder, strict=False, ignore_hash=False)
                                   # {ok, data, отчёт, проблемы, предупреждения,
                                   #  изменений, операций, ошибка}
se.write_json(data, path)          # редакция на диск, размер
se.strip_revision(data)            # (чистый JSON, отчёт): без блока «Редакция»,
                                   # служебных полей и ссылок «ИЗМ-N»
se.build_standard(source, meta=..., replacements=[...], keep=[...],
                  renumber=True)   # проверка без записи
se.new_standard(source, out, ...)  # то же + запись (overwrite=False)
se.validate_standard(data)         # (проблемы, предупреждения)
se.cabinets_of(data)               # шкафы для диалога
se.build_docx(data_or_path, out, toc=True)
se.docx_interpreter()              # Python с python-docx (или None)
```

Все ошибки возвращаются словарём (`ok: False`, `ошибка`), исключения наружу
не выходят — окна показывают текст, консоль печатает и возвращает код 1.

## Особенности, на которые стоит знать

* **Временные каталоги** создаются в `output/.tmp`: `tempfile.mkdtemp` на
  Windows ставит DACL 0700, и под политикой редактора в такой каталог нельзя
  ни писать, ни смотреть. Мост подменяет `tempfile` в загруженных модулях
  стандартов (`_TempDir`), поэтому «Собрать редакцию» (F6) и консольная
  команда `preview` работают и без доступа к `%TEMP%`; сами файлы
  `standard_editor/*.py` при этом не меняются. Имена временных файлов в
  журнале сборки заменяются обратно на исходные `*.изм.txt` — в отчёте видно
  `ИЗМ-3.изм.txt`, а не `003.json`.
* **Окна открываются на том же мониторе.** `standards_ui._place_on_parent`
  ставит новое окно по прямоугольнику главного окна (центр, а если окно
  больше — левый верхний угол); диалоги `changes_gui` используют такой же
  `_place_over_parent`. Без явных координат Windows отправляет новое окно
  на основной монитор, даже если редактор открыт на другом.
* **Статусы изменений**: файл со `СТАТУС: отменено` разбирается, но операций
  не содержит и в сборку не попадает (в журнале — «ИСКЛЮЧЕНО»). Старшая
  версия одного изменения вытесняет младшие.
* **DOCX без `python-docx`**: в Python 3.14 пакета может не быть. Мост ищет
  интерпретатор, где он есть (сейчас `C:\Python313\python.exe`), и строит
  отчёт отдельным процессом; результат тот же, окно показывает, кто строил.
  Если интерпретатора нет — окно подсказывает команду установки.
* **Каталог изменений** по умолчанию — `standard_editor/changes_text`, но в
  окнах его можно указать любой (удобно держать изменения рядом с проектом).
* **Новый стандарт** пишется только после успешной проверки
  (`make_standard.validate_standard`): ошибки блокируют запись,
  предупреждения нет. Отказ «файл уже существует» — штатное поведение,
  перезапись только по подтверждению.
* **Папка `standard_editor/`** в git не входит (как и `standards_base/`).
  Без неё редактор работает, а вкладка «Стандарты» сообщает, что папка не
  найдена.
* **В собранном приложении** папка инструментов лежит в `db/standard_editor`
  рядом с exe (модули, базы стандартов и изменения). Путь ищется через
  `apppaths`: `db` → рядом с программой → внутри сборки; те же правила для
  `standards_base`. См. [PACKAGING.md](PACKAGING.md).

## Проверки

```bash
python tests/test_standards_editor.py            # данные, файлы, окна
python tests/test_standards_editor.py --no-gui   # без tkinter
```

Тест проверяет: связку с папкой, разбор четырёх изменений (включая
вытеснение версии и отменённый статус), сборку и чтение редакции обратно,
сброс пометок редакции (блок «Редакция», служебные поля и ссылки «ИЗМ-N»),
новый стандарт с подмножеством шкафов и перенумерацией, отказ перезаписи,
отчёт DOCX, все пять окон и проводку вкладки в `main.py`.
